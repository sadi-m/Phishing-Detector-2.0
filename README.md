Phishing Detector 2.0

Phishing Detector 2.0 — это веб-приложение для анализа интернет-ссылок и выявления признаков фишинговых и потенциально опасных URL. Проект разработан на Python с использованием Flask и представляет собой развитие первоначальной версии системы обнаружения фишинговых ссылок.

Приложение работает как локальный веб-сервис по адресу http://127.0.0.1:8080 и предоставляет пользователю интерфейс для проверки URL. Система анализирует введённую ссылку, определяет подозрительные признаки и сохраняет результаты проверок в базе данных.

В версии 2.0 основной акцент был сделан не только на функциональности, но и на безопасности самого приложения. Были устранены потенциально опасные настройки и добавлены дополнительные механизмы защиты веб-приложения.

Основные возможности
анализ URL на наличие признаков фишинга;
регистрация и авторизация пользователей;
разграничение прав обычного пользователя и администратора;
хранение истории проверок;
административная панель;
управление пользователями;
просмотр информации, необходимой администратору для контроля системы;
экспорт данных в Excel;
защита пользовательских форм и административных операций;
ограничение частоты запросов для предотвращения перебора и спама.
Улучшения безопасности в версии 2.0

В проекте был реализован ряд мер защиты:

Безопасное управление секретным ключом.
Секретный ключ больше не хранится непосредственно в исходном коде. При первом запуске приложение генерирует уникальный ключ и сохраняет его локально.
Удаление встроенных учётных данных администратора.
Пароль администратора больше не прописан непосредственно в программном коде.
Отключение Flask Debug Mode.
Приложение запускается без небезопасного режима отладки, что снижает риск раскрытия внутренней информации приложения.
Защита от CSRF-атак.
Для операций, изменяющих состояние приложения, используются CSRF-токены. Это защищает формы авторизации, управления пользователями и другие критические действия.
Защищённые административные операции.
Опасные действия администратора переведены с GET-запросов на защищённые POST-запросы.
HTTP Security Headers.
Добавлены защитные HTTP-заголовки, препятствующие встраиванию приложения в сторонние страницы, подмене MIME-типов и некоторым видам XSS-атак.
Защищённые cookie.
Настроены безопасные параметры cookie сессии, а срок действия пользовательской сессии ограничен 8 часами.
Rate Limiting.
Ограничена частота регистрации, авторизации и проверки URL. Это снижает риск перебора паролей, автоматизированных запросов и спама.
Усиленная валидация данных.
Добавлена дополнительная проверка имён пользователей, паролей, отзывов и длины URL.
Защита пользовательской приватности.
Убран автоматический запрос геолокации пользователя во время регистрации.
Безопасный Excel-экспорт.
Добавлена защита от Excel Formula Injection — вредоносные значения не должны интерпретироваться Excel как формулы.
Защита конфигурации проекта.
Добавлен .gitignore, предотвращающий случайную публикацию базы данных, секретов и других конфиденциальных файлов в Git-репозитории.
Документация по безопасности.
Создан файл SECURITY.md, содержащий рекомендации по безопасному развёртыванию приложения.
Шаблон конфигурации.
Создан .env.example, демонстрирующий необходимые параметры конфигурации без публикации реальных секретов.
Архитектура проекта

Упрощённо работу системы можно представить следующим образом:

Пользователь → Веб-интерфейс → Flask → Модуль анализа URL → База данных → Результат проверки

Администратор дополнительно получает доступ к:

Авторизация → Административная панель → Управление пользователями / история / экспорт данных

Итог

Phishing Detector 2.0 представляет собой не просто программу для определения фишинговых ссылок, а полноценное защищённое веб-приложение, объединяющее анализ URL, систему пользователей, административное управление, хранение истории и комплекс мер защиты веб-приложения.

Главное отличие версии 2.0 от первоначальной версии заключается в переходе от простого рабочего прототипа к более полноценной системе, в которой безопасность учитывается как при анализе фишинговых ссылок, так и при защите самого приложения от веб-атак.
